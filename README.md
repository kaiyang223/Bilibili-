# 聊天记录浏览器

一个能够浏览 b 站聊天记录的本地网站 —— 把聊天记录导出文件（`.txt`）变成可浏览的对话界面，并能打包成**双击即可离线查看**的单文件。

- **形态**：单个 HTML 文件，双击即用，无需安装
- **产物**：`dist/聊天记录浏览器.html`（单文件，仓库内已附带可直接使用）
- **隐私**：不联网上传任何数据，解析、渲染、导出全部在本地浏览器内完成

## 快速开始

1. 双击 `dist/聊天记录浏览器.html`
2. 把聊天记录 `.txt` 拖到页面上（也可以点「选择文件」，或直接 <kbd>Ctrl</kbd>+<kbd>V</kbd> 粘贴文本）
3. 自动整理成对话视图；要留档就点右上角「导出」

**所有数据都留在这台电脑上** —— 页面不上传任何内容，也不访问除图片地址以外的网络资源。

首次加载只渲染前 220 条，向下滚动会自动续接，上万条记录也不会卡。

## 输入的聊天记录格式

每行一条消息，形如：

```
2025/03/14 09:30:00 user_001说： 这是一条文字消息
2025/03/14 09:31:20 user_002说： https://example.com/photos/sample.jpg
```

> 上例中的时间、ID 与链接均为示意占位，不代表任何真实数据。

解析规则：

| 项目 | 兼容情况 |
|---|---|
| 日期分隔符 | `/`、`-`、`.` 都可以 |
| 时间 | 秒可省略；`说` 前后空格可有可无 |
| 冒号 | 全角 `：` 与半角 `:` 都支持 |
| 发送者 | 时间戳与 `说：` 之间的任意文本，作为用户标识 |
| 链接 | `http(s)://…` 自动变成可点击链接 |
| 图片 | 以图片扩展名结尾，或来自常见图片地址的链接，自动内联展示 |
| 表情 | `[表情名]` 形式的标记自动还原为表情图 |
| 结构化消息 | 形如 `[{"text":"…"}]` 的消息渲染为居中的系统提示 |
| 无法识别的行 | 自动并入上一条消息（保留换行），不会丢内容 |

文件按 UTF-8 读取，自动忽略 BOM。

## 功能说明

### 导入

- 拖放到页面任意位置
- 点「选择文件」
- 点「从剪贴板粘贴」，或直接 <kbd>Ctrl</kbd>+<kbd>V</kbd>（支持粘贴文件或纯文本）
- 点右上角 ✕ 可重新导入

### 浏览

- 左右分栏气泡：第一位参与者在左、第二位在右；头像按用户标识取色，不同用户颜色必定不同
- 跨天自动插入日期分隔线（含星期）
- 每条消息带时间戳，悬停可见精确到秒的时间
- **窗口化渲染**：页面上最多保留 1500 条消息，滚动时自动加载与回收，浏览上万条记录依旧流畅

### 图片

- 消息里的图片自动内联成卡片，多图自动排成网格
- 按需加载（滚动到视野内才请求），加载前有骨架动画
- 超长截图自动限高，并提示「长图 · 点击查看完整」
- 点击打开灯箱：滚轮缩放、拖拽平移、双击放大、<kbd>←</kbd>/<kbd>→</kbd> 翻页、<kbd>0</kbd> 复位
- 灯箱内可下载原图或在新窗口打开

### 表情

- 内置 3,000 余条常用表情的名称映射
- 其中 80 张以 base64 内嵌，**断网也能正常显示**
- 匹配不到的表情自动回落到 emoji，不会出现裸露的 `[xxx]`

### 搜索与跳转

- 顶部搜索框：全文检索（含链接文字与表情名），命中处高亮
- 显示 `当前/总数`，<kbd>Enter</kbd> 下一个、<kbd>Shift</kbd>+<kbd>Enter</kbd> 上一个；目标不在当前窗口时会自动重新定位
- 日期下拉：按天跳转
- 右下角悬浮按钮：回到顶部 / 跳到最新

### 主宾互换

工具栏的双向箭头按钮，一键把左右两位对调，按钮高亮表示当前处于互换状态，再点恢复。想让自己显示在左边还是右边都能随时切。

### 主题

右上角图标切换明暗主题；首次打开会跟随系统设置，选择会记住。

## 导出离线文件

点右上角「导出」，生成一个**自包含的单文件 HTML**：图片转成 base64 内嵌，数据和渲染引擎一并打包。双击即可打开，**查看时完全不需要联网**。

三种图片处理方式：

| 方式 | 说明 |
|---|---|
| **压缩内嵌**（推荐） | 图片按指定最长边重新编码后写入，体积可控，离线完整可看 |
| **原图内嵌** | 保留原始画质，体积最大 |
| **仅保留链接** | 不下载图片，文件极小，查看时需要联网 |

选择「压缩内嵌」时可用滑杆调整最长边（480–1440 px），面板会实时预估文件体积。

### 体积参考

体积主要取决于**图片数量**和**所选尺寸**。以「压缩内嵌、1080 px」为例的经验值：

| 图片数量 | 大致体积 |
|---|---|
| 500 张 | 约 30 MB |
| 1,000 张 | 约 60 MB |
| 2,000 张 | 约 120 MB |

不同最长边之间的**相对**体积：

| 最长边 | 相对 1080 px |
|---|---|
| 1440 px | 约 130% |
| **1080 px**（默认） | 100% |
| 960 px | 约 93% |
| 720 px | 约 70% |
| 480 px | 约 50% |

### 耗时

耗时主要在下载图片：首次导出大致**每 1,000 张需要 1 分钟左右**（取决于网速）。图片进入浏览器缓存后再次导出会快得多。

导出的文件双击打开通常 1 秒左右即可交互，图片按需解码，滚动不卡。

导出过程中会显示进度、失败张数与耗时；个别图片下载失败会自动重试，仍失败则保留原链接（有网时依旧能显示）。

## 参与者档案

昵称与头像按**用户标识**绑定，保存在浏览器本地，跨聊天记录通用 —— 同一个标识在任何记录里都会显示你设定的名字和头像。

设置方式：

- 直接点任意消息上的头像 → 选本地图片（自动裁成方形、压到 192 px 后保存）
- 点消息上方的昵称，或工具栏的「会话信息」，可改名、换头像、重置

**档案管理**（工具栏用户组图标）可统一管理本机全部档案：

- 浏览所有档案，当前会话的排在前面，并标注消息条数
- 按昵称或标识搜索
- 改名、换头像、删除单条
- 导出为 JSON（备份 / 迁移到别的浏览器）、导入 JSON（合并并报告增量）、清空全部

存储位置为浏览器 `localStorage` 的 `chatview.profiles.v1`，结构如下：

```json
{
  "<用户标识>": { "n": "显示名", "a": "data:image/webp;base64,UklGR…" }
}
```

导出离线副本时会带上已设置的昵称和头像；在副本里也能点头像换图，但只影响本次浏览，不会写回文件。

> 清理浏览器数据会导致档案丢失，重要的话建议先「导出档案」备份。

## 构建

修改源码后重新生成单文件产物：

```bash
python build.py
```

`build.py` 会把 `src/app.html` 里的占位符替换为表情字典与 `src/engine.js`，并校验注入是否完整，
产物输出到 `dist/聊天记录浏览器.html`。

如需更新表情资源（会联网一次，重新拉取表情清单并生成内嵌图）：

```bash
python build_assets.py
```

> ⚠️ 修改 `src/engine.js` 时注意不要在代码里出现 `</script>` 字面量，`build.py` 会直接报错阻止生成。

## 测试

测试脚本本身**不含任何具体数据**，要验证的记录通过环境变量传入：

```bash
CHAT_TXT=<聊天记录路径> node e2e.mjs
# Windows 下： set CHAT_TXT=D:////path////to////chat.txt && node e2e.mjs
```

如需严格比对解析数量，可再给出期望值（不设则只校验「解析出了合理内容」）：

```bash
CHAT_TXT=<聊天记录路径> CHAT_MSGS=<消息条数> CHAT_USERS=<人数> CHAT_IMGS=<图片数> node e2e.mjs
```

使用**系统自带的 Edge**（headless + CDP 协议）驱动，不需要安装 Playwright 或 Chromium。

覆盖的断言包括：

- 导入与解析准确性（消息条数、参与者、图片数与表情数逐项核对）
- 图片与表情是否真的能加载成功
- 滚动加载与页面节点数量上限
- 搜索命中、高亮、上下跳转，日期跳转
- 灯箱打开 / 翻页 / 关闭
- 主题切换、会话统计
- 头像导入、昵称绑定、重新导入后自动恢复
- 主宾互换（左右数量精确对调）
- 档案管理的搜索、改名、导出、清空、导入、删除
- 离线导出的自包含性，以及副本打开后图片是否全部本地读取

```bash
CHAT_TXT=<聊天记录路径> node full-export2.mjs 720   # 全量导出实测（参数为最长边）
CHAT_TXT=<聊天记录路径> node shot.mjs               # 生成界面截图到 shots/
python cleanup.py                                   # 清理上面几步产生的临时文件
python privacy_audit.py                             # 扫描项目里是否残留个人信息
```

测试完成后会自动删除临时浏览器 profile。

## 技术要点

- **窗口化渲染**：页面中只保留有限条消息，滚动到边界时从远端扩展、从另一端回收并同步修正滚动位置，保证视觉不跳动。这是上万条消息仍能流畅浏览的关键。
- **图片按尺寸取用**：若图片地址来自支持尺寸参数的图床（在链接后追加 `@<宽>w_<高>h.webp` 之类的参数），工具会自动取缩小版本 —— 浏览时用缩略图加快滚动，导出时按所选尺寸取图，单张体积可降到原图的十分之一左右。
- **单文件导出**：优先取缩小版图片（小且快），不支持缩放的图片再走 canvas 本地压缩；配合 6 路并发与退避重试。数据和引擎一起序列化进 HTML，因而副本无需联网，搜索、灯箱、互换等功能完整可用。
- **表情双保险**：完整映射用于在线解析，80 张内嵌图用于离线兜底，再失败则回落到 emoji。
- **滚动兜底**：除 `IntersectionObserver` 外还挂了一层 `scroll` 监听（用 `setTimeout` 节流），避免浏览器在长时间高负载后暂停渲染帧导致加载失效。

## 已知限制

- 消息里的图片来自外部图床，首次浏览需要联网；原图被删除或图床调整时会显示「图片加载失败」
- 单文件导出的体积与图片数量成正比。图片很多时建议用「压缩内嵌」并适当调低最长边
- 仅解析文本型的聊天记录导出文件，不做任何接口调用
- 昵称与头像保存在浏览器本地，换浏览器或清理站点数据会丢失，可用「导出档案」迁移
- 解析规则针对 `时间 + 发送者 + 说： + 内容` 这一类格式做了最大兼容，其他平台的记录可能需要微调 `src/engine.js` 中的 `HEAD_RE` / `SAY_RE`
